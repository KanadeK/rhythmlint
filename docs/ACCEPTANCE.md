# Acceptance commands

These commands distinguish local implementation, package readiness, and public release.
Run them from the repository root.

## 1. Clean installation

```bash
node --version
npm ci --registry=https://registry.npmjs.org/
npm audit --omit=dev --audit-level=high --registry=https://registry.npmjs.org/
```

Expected: Node 20+ for runtime. The full release gate requires Node 22.8+; Node 24 is the
reference environment. Audit reports zero high-severity runtime vulnerabilities.

## 2. Build and ordinary tests

```bash
npm run typecheck
npm test
```

Expected: strict typecheck passes; 28 tests pass. Tests execute the parser, all rules,
recurrence exceptions, DST, redaction, diff, overlay, reporters, compiled CLI, and
standalone bundle.

## 3. Enforced coverage and static boundary

```bash
npm run lint
npm run test:coverage
```

Reference result for v0.1.0:

- lines: 95.34%
- branches: 89.08%
- functions: 96.92%

Enforced minimums are 88% lines, 78% branches, and 88% functions. Static check rejects
unfinished-work markers, private-key/token shapes, co-author trailers, version drift, and
network fetches in `src`.

## 4. Real CLI behavior

```bash
node dist/cli.js audit examples/before.ics \
  --config examples/rhythmlint.config.json --from 2026-08-03 --fail-on none
node dist/cli.js diff examples/before.ics examples/after.ics \
  --config examples/rhythmlint.config.json --from 2026-08-03 --fail-on none
node dist/cli.js overlay examples/before.ics \
  --config examples/rhythmlint.config.json --from 2026-08-03 \
  --out proposed-holds.ics
```

Expected audit: score 0, 3 errors, 20 warnings. Expected diff: score +100, meeting minutes
-880, 23 resolved findings, no introduced findings. Overlay writes valid VCALENDAR and may
return `1` only if free capacity cannot satisfy every focus requirement.

Without `--fail-on none`, auditing `before.ics` must return `1`. A malformed config or ICS
must return `2`.

## 5. Deterministic committed evidence

```bash
npm run demo:check
```

Expected: six artifacts match regenerated bytes. To intentionally update them after a
semantic change:

```bash
npm run demo
npm run demo:check
```

Review both the source fixture diff and the generated report diff.

## 6. Package and standalone smoke

```bash
npm run package:release
node release/rhythmlint-0.1.0-standalone.mjs --version
node release/rhythmlint-0.1.0-standalone.mjs audit examples/after.ics \
  --config examples/rhythmlint.config.json --from 2026-08-03
```

Expected: version `0.1.0`; repaired calendar exits `0`; `release/` contains the standalone
file, npm tarball, demo HTML, overlay ICS, third-party notice, manifest, and checksums.

PowerShell checksum verification:

```powershell
Get-FileHash -Algorithm SHA256 release\* | Sort-Object Path
Get-Content release\SHA256SUMS.txt
```

Linux/macOS:

```bash
(cd release && sha256sum -c SHA256SUMS.txt)
```

## 7. One-command release gate

```bash
npm run release:check
git status --short
git diff --check
```

Expected: release check passes, tracked demo artifacts are current, and the worktree is
clean after committed delivery.

## 8. Public release closure

Local green checks are not publication. Verify:

```bash
gh auth status
gh repo view KanadeK/rhythmlint --web=false
gh run list --repo KanadeK/rhythmlint --limit 20
gh release view v0.1.0 --repo KanadeK/rhythmlint
gh api repos/KanadeK/rhythmlint/contributors
git shortlog -sne HEAD
git log --format='%an <%ae>|%cn <%ce>|%B' --all
```

Then download every release asset to a fresh temporary directory, verify
`SHA256SUMS.txt`, execute the downloaded standalone asset, and open the Pages URL. Only
after those checks is a release-complete notification accurate.
